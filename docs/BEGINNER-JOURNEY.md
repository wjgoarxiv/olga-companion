# Beginner simulation journey

## Authorized direction

Goal: an OLGA beginner can define a simulation scheme, create or safely modify a
case, review preflight, approve a run, plot results and interpret evidence from
this app. An installed, licensed OLGA runtime, a connected AI provider and usable
fluid data remain prerequisites, not capabilities that UI copy can manufacture.

Preserve the current light workbench, local fonts, semantic colors and existing
uncommitted changes. Use Impeccable's product register: familiar controls, fixed
type sizes, restrained color, useful empty states and no decorative motion.
No release, remote, signing, credential or permission changes are authorized.

## Finite UI slice

- Chat: a five-step guide for create, edit, validate, run and analyze.
- Native disclosure: expanded at first use; available folded during conversation.
- Step selection: explains the operation and its evidence checkpoint, not progress.
- Prepare question: fills the existing editable composer and focuses it. Never
  sends, publishes, approves or executes an action by itself.
- Recovery: open Settings for AI connection; open Workspace to select an existing
  case. Offline or busy states explain why preparation is disabled.
- Advanced starters: retain the existing shortcuts behind a disclosure.
- Narrow layouts: stack step list and detail; wrap Korean and long case names;
  preserve 44px controls, visible focus and the single scrolling timeline.
- No new motion. Existing reduced-motion policy remains in force.

## Composer and first-screen revision

Replace the single-line composer with a native multiline textarea. Enter inserts
a newline; Ctrl/Command+Enter submits only when online, non-empty and idle.
IME composition must not submit. An explicit Clear action changes only the draft
and returns focus. Use native content sizing where supported, three rows as the
fallback, a bounded height and an internal scroll for longer questions.

Remove the duplicate dark context card and repeated case names from Chat; keep
the shared case selector. At narrow widths use a labeled native step picker
instead of the five-row list, so the selected task and action stay closer to the
top. Keep all five operations, recovery paths, draft preservation and the separate
human approval boundary. Scope the guide definition list to block layout rather
than inheriting the evidence grid. No backend behavior changes in this revision.

## Acceptance and limitations

Verify step selection, question preparation, manual send, keyboard focus return,
no-case recovery, missing-provider recovery, offline state and conversation
continuation. Run the installed frontend-ui-ux probe's full RS matrix on the built
entry. Keep local render evidence separate from an independent review.

Actual OLGA runs, provider responses, Windows packaged behavior, screen-reader
speech and engineering validity need their own real-surface checks. A successful
UI probe does not prove the entire scientific lifecycle.

## Journey revision 2: actions that are real, and states that are true

- Case creation needs the user's own fluid label and PVT table, source and sink
  pressure and temperature, pipe roughness and an explicit adiabatic or ambient
  heat-exchange choice. None has a default; the assistant must ask for each.
- Run separates a receipt restored from an earlier session ("이전 실행 기록") from
  the run started in this view, hides progress for the former, names what blocks
  Approve and run, and shows the solver's fault lines and a next step. An uncertain
  run is never restarted automatically.
- Results label each file as matching its run receipt, changed after the run, or
  without a receipt, open on the active case's own results, and give the common
  OLGA mnemonics (PT, TM, HOL, GT, QT) a plain name beside the code.
- Chat history is titled by the first question and shows when it last changed.
- Text below 11px is removed except the brand lockup; chart axis text is a true 12px.
