## Criteria

Each cluster gets 1-5 on five criteria. Weighted total = sum(weight x score).

| Criterion | Weight | 5 means | 1 means |
|---|---|---|---|
| User value | 0.35 | Daily OLGA/Multiflash engineer feels it every case; increment over what is already shipped is large | Rare use, or mostly already shipped |
| Safety | 0.20 | Read-only or deterministic; keeps approval gate and new-copy publish intact | Adds a new write, execute or network path, or loosens a gate |
| Implementation cost | 0.20 | Cheap (days, existing infra) | Multi-week or needs unreviewed layers (Tauri, broker, licence behaviour) |
| Verifiability | 0.15 | Deterministic pytest on fixtures or fake_olga proves it | Needs real OLGA runs, real users or judgement |
| Link to R1-R15 | 0.10 | Fixes or depends directly on several findings | No link |

Value is scored on the increment over the current code, so clusters that grep shows as already shipped are scored down (sweep authoring, approval integrity, range check). Ties are broken by value, then link.

## Method and limits

Clustering was done by hand-written keyword and title groups over all 471 titles (every idea is in exactly one cluster; member counts add to 471). Several clusters are broad (install/update has 35 ideas, beginner lessons 29) because the raw set repeated a theme under many names; the count shows how often it was proposed, not how good it is. Frequency was not used as a score input, because five parallel lenses produced near-duplicates by construction.

## Top 10

Common caveat: all scores are judgement on a 1-5 scale; values are mine, not measured. Marked (H) means the value or feasibility is a hypothesis that no code or user evidence yet supports.

### 1. Stop-reason card with evidence line and plain wording in en and ko (cluster of 15) - 4.45
- What: show OLGA's own stop message, the cited .out line, and a pointer to the keyword or element involved, in the UI language. Not a fix, a clear reading.
- Main risk: pointing at the wrong keyword or element reads as a diagnosis; the stop reader sees only OLGA's text, so the link must be conservative and say "unknown" when unsure.
- Cheapest first test: fix the R2 regex, then run explain_stop over 5 real or fixture .out files (include "kg/s", "m/s") and check the card text has no `[private-path]` inside units. Pure pytest.
- Gives up: no automatic remedy (that is the remedy-loop cluster, rank 11 in the table, which stays separate and gated); no learning from history.
- Links: R2 (units corrupted in stop reasons), R15 (mixed languages). Feasibility: verified that explain_stop, RunFailurePanel.tsx and RunStrip.tsx exist; keyword link (H).

### 2. Spreadsheet, CSV and BI export of results (cluster of 7) - 4.45 (ties with idea 1; rank 1 under alt)
- What: NaN-safe, multi-series CSV with a header row of unit, an Excel-friendly option (BOM, semicolon for ko-KR), provenance line.
- Main risk: Excel silently rewrites values (dates, thousands) so an exported number differs from the screen; engineers then trust the sheet.
- Cheapest first test: export a series containing a NaN and a 15.1 degC value, check the file round-trips unchanged and opens as numbers in Excel on a ko-KR machine. First half is pytest, second half is manual.
- Gives up: no live Power BI link, no native xlsx writer, no scheduled export.
- Links: R3 (NaN fails whole export; offset round trip), R8 (locale encoding). Feasibility: verified result_csv_exports.py writes plain utf-8, one series, no BOM.

### 3. Locale-safe number parsing, units and display (cluster of 9) - 4.35
- What: one parser for pipe-table, .tab and approval values that rejects ambiguous text such as "1,234" instead of guessing; display follows the locale choice.
- Main risk: guessing wrong turns 1,234 into 1.234 with no visible error; rejecting too much frustrates users.
- Cheapest first test: property test with "1.234,5", "1,234.5", "1,5", "1 234" through pipe_table import and check each is accepted exactly or refused with a message. No OLGA needed.
- Gives up: lenient auto-detection of mixed formats in one column.
- Links: R3, R7 (float compare), R8. Feasibility: delimiter sniffing is verified in pipe_table._csv_rows; decimal-comma handling is NOT a gap: pipe_table._number already accepts "0,05" and refuses "1,500" (critic check). Remaining gap is other parse sites (see Critic corrections).

### 4. Golden-case regression set and canary checks (cluster of 3) - 4.35
- What: a small fixture suite (cases, .tab, results with NaN, PVTFILE comments, ENDTIME tokens) run against fake_olga on every change, starting with a failing test per R1, R2, R3, R5, R7, R11.
- Main risk: fixtures freeze current wrong behaviour, and fake_olga is not real OLGA, so green does not mean OLGA accepts the case.
- Cheapest first test: write the six reproducing tests from FINDINGS.md first; they should fail before the fixes and pass after.
- Gives up: no end-to-end real-solver coverage; maintenance time over features.
- Links: R1, R2, R3, R5, R7, R11. Feasibility: verified golden genkeys and fake_olga exist; no end-to-end harness yet.

### 5. Fluid table provenance, staleness and dependency refresh (cluster of 11) - 4.35
- What: at make_tab, write a sidecar with the sha256 of the .mfl, the Multiflash version and the grid; at preflight, compare and warn when the .mfl or grid changed since the .tab was built. Refresh stays approval-gated.
- Main risk: stamping a wrong table as good if R4 (ignored load_errors) is not fixed first; also false stale alarms when a .tab was made elsewhere.
- Cheapest first test: build a .tab from a fixture .mfl, edit the .mfl, and check preflight reports stale; then repeat with a .tab that has no sidecar and check it says "unknown", not "stale".
- Gives up: no automatic refresh, no cross-project dependency graph.
- Links: R4, R10, R14. Feasibility: no staleness code found; Multiflash run itself needs the real engine to verify (H).

### 6. Plain-language bilingual approval cards and OLGA glossary (cluster of 20) - 4.30
- What: backend messages (findings, failure titles, PVT ranges) go through one catalogue keyed by locale, OLGA keywords stay in English with a gloss; en and ko render the same card.
- Main risk: a Korean gloss of an OLGA keyword that is wrong or misleading in a safety-relevant approval card.
- Cheapest first test: a script that lists backend user-facing strings not in the catalogue (R15 sites first), and rendering one failure and one approval card in both locales.
- Gives up: free-form LLM explanations on the card; third language.
- Links: R15. Feasibility: verified en.ts and ko.ts have equal line counts (2169); backend strings are not catalogued.

### 7. Cross-run overlay and measured-vs-simulated comparison (cluster of 7) - 4.25

- Links: R13 (keyword edits stay in the sandbox, so only some edits are visible), R7. Feasibility: parent and candidate diff verified in case_transaction_apply; free two-case view is (H).

### 10. Figure export and chart UX: timestep, event markers, snapshots (cluster of 6) - 3.95

- Links: R9. Feasibility: verified result_plot_exports.py and publication_plot.py exist; FINDINGS R9 is a code read, not a measured timeout.
